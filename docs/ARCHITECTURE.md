# Архитектура

Один процесс-шлюз принимает сообщения, Laya решает за десятки миллисекунд, LLM вызывается только для генерации, а всё внешнее исполняется после проверки политик.

```
Терминал / веб / Telegram → Шлюз → Lane Queue → Агентный цикл → Канал
                                                   │
      шорт-лист (BM25 + расширение запроса) → Laya/LLM выбирает тул → LLM заполняет аргументы
      → проверка описаний (rug pull) → политика (эффекты, taint, мандаты) → апрув в канале
      → исполнение: встроенные тулы | навыки | MCP (stdio в песочнице, HTTP) → журнал
```

## Правило разделения

**Тонко там, где модели растут сами** (рассуждение, планирование, код), **толсто там, где рост моделей не помогает** (безопасность, состояние, идентичность, проверка исхода, деньги).

## Laya: что она умеет и чего нет

Laya Multilingual ([карточка модели](https://huggingface.co/convaiinnovations/laya-multilingual)) отвечает на типизированные вопросы за один проход: выбор из вариантов (`choice`) и да/нет (`noul`). Текст она не генерирует и аргументы тулов не заполняет.

Ограничения из карточки, которые определяют дизайн:

- Без дообучения на typed-decisions близка к случайному выбору (0,342 против 0,318). Поэтому её рекомендации сначала работают в **теневом режиме**, а решает LLM.
- Поставляется некалиброванной и завышает уверенность. Порог уверенности задаётся после калибровки на ваших данных.
- `choice` держим до 16 вариантов; иерархический выбор для больших наборов.
- `score` не используем (позиционный сдвиг); `noul` заменяем на `choice` с ключами A/B.
- Контекст 1024 токена по умолчанию.

В коде это интерфейс `DecisionEngine` в `packages/brain`.

### Sidecar и включение

Laya работает в отдельном процессе `sidecar/laya_server.py` (пакет `laya`, API из карточки модели: `laya.load(...)`, `agent.predict(inputs, questions)`). Агент говорит с ним по HTTP только на 127.0.0.1: состояние содержит ваши личные тексты. Протокол: `POST /predict {state, question}` → `{probs, exact}`. Если установленная версия `laya` отдаёт только выбранный вариант без вероятностей, sidecar помечает ответ `exact: false`, и агент считает уверенность неизвестной (0,5, ниже порога), то есть решает LLM. Sidecar проверен с подменной `laya`; на настоящих весах его ещё нужно прогнать, потому что из среды разработки модель недоступна.

Путь к самостоятельным решениям:

1. **Теневой режим** (по умолчанию). Решает LLM, Laya отвечает параллельно, статистика согласия сохраняется в `cascade.json`, пары из нетронутого taint контекста пишутся в `decisions.jsonl` вместе с вероятностями Laya.
2. **Калибровка.** `august calibrate` подбирает температуру по логу (метка: выбор LLM) и показывает ECE до и после.
3. **Включение.** `august laya activate` доступно после 200 решений с согласием от 90%. После включения Laya решает, когда откалиброванная уверенность выше порога (0,7), иначе решает LLM.

Без sidecar вместо Laya стоит `HeuristicEngine`, и всё остальное работает так же.

## Каскад решений

1. Индекс способностей (BM25) сужает набор до ≤ 16 кандидатов. Поиск лексический, поэтому для других языков есть два механизма: у тула могут быть `keywords` на нескольких языках, а если кандидатов меньше трёх, LLM один раз за задачу переводит запрос в английские ключевые слова (`LlmQueryExpander`, с кэшем; уходит только запрос человека, не результаты тулов). Эмбеддинги запланированы на v1.
2. Laya выбирает кандидата или «ни один».
3. Если уверенность ниже порога, решает LLM; пара «вход → решение LLM» уходит в датасет дообучения.
4. LLM заполняет аргументы по JSON-схеме тула, валидатор проверяет их.
5. Политики оценивают эффекты вызова и метки данных: разрешить, спросить или запретить.
6. Если политика говорит «спросить», человек получает запрос в своём канале с описанием того, что именно произойдёт (`describeCall`: команда установки, адрес, секреты).
7. Исполнение: встроенный тул, навык или MCP-сервер (в песочнице, если она есть). Результат из недоверенного источника оборачивается в ограду со случайным id и помечает задачу taint.

## Лестница дистилляции

Повторяющаяся задача спускается по ступеням: **0** LLM с нуля → **1** навык → **2** workflow с развилками Laya → **3** рефлекс без LLM. Подъём на ступень требует трёх подряд подтверждённых исходов (проверка или eval, не слова модели); сбой возвращает на ступень ниже. Ступень 3 с контролируемыми эффектами требует апрува человека, а каждый N-й запуск рефлекса идёт через workflow для проверки. См. `packages/ladder`. Пакет готов и покрыт тестами; запись исходов из агентного цикла и автоматическое создание навыков из повторов запланированы на v1.

## MCP-серверы

`packages/mcp` говорит с серверами по stdio (дочерний процесс) или по streamable HTTP (удалённый сервер). Особенности, которые определяют дизайн:

- **Эффекты MCP не объявляет.** Есть только необязательные подсказки (`readOnlyHint` и др.), и враждебный сервер может в них соврать. Поэтому подсказкам верим только серверам с уровнем `known` и `verified`; всем остальным и любому тулу без подсказок присваиваем `read + write + network`, то есть каждый вызов идёт через апрув или мандат.
- **Результаты по умолчанию недоверенные** (получают taint), кроме тулов доверенного сервера с `readOnlyHint` и закрытым миром.
- **Чистое окружение.** Серверу передаются `PATH` и несколько системных переменных, плюс явно перечисленное в конфиге. Ключи и токены агента до него не доходят.
- **Имена**: `сервер.тул`, недопустимые символы заменяются на `_`, коллизии после замены отклоняются; описание обрезается до 1000 символов.
- **Проверка до каждого вызова.** `McpHost.liveDescriptors` заново запрашивает список тулов, реестр сверяет хеш с закреплённым; изменение отключает сервер до повторного апрува. У встроенных способностей проверки нет (`undefined`).
- **Лимиты**: таймаут запроса, размер сообщения, размер результата, число страниц `tools/list`. Запросы от сервера к нам (sampling, roots) отклоняются, кроме `ping`.
- stderr сервера копится для диагностики и в контекст модели не попадает.
- **HTTP-транспорт**: только https (или localhost), ответы JSON или SSE, `Mcp-Session-Id`, редиректы не следуют (они унесли бы заголовки с ключами), истёкшая сессия отключает сервер. OAuth пока нет, заголовки берутся из хранилища секретов.

### Песочница

`sandboxSpec` оборачивает команду сервера. На Linux это bubblewrap: вся ФС только для чтения, `/home`, `/root`, `/run` скрыты (ключи, SSH-агент, сокеты keyring), своя домашняя папка в `~/.august/data/sandbox/<id>` (кэш npm/uv сохраняется), свой `/tmp`, отдельные пространства имён, сеть только если `network: true` (по умолчанию да, большинству серверов она нужна). На macOS это sandbox-exec: чтение и запись в домашней папке запрещены, кроме своей папки сервера. Режимы: `auto` (по умолчанию: изолировать, если есть чем, иначе запустить и предупредить), `required` (без песочницы не запускать), `off`. `august doctor` показывает, что доступно.

## Поиск и установка способностей

Агент видит три своих тула (`august.*`):

- `find_tools`: поиск в [официальном реестре MCP](https://registry.modelcontextprotocol.io) (API v0). Результаты считаются недоверенным текстом. Сеть покрыта постоянным мандатом на хост реестра, поэтому поиск идёт без вопросов, но не из заражённого контекста.
- `install_tool`: план установки из записи реестра. Предпочитается локальный пакет с точной версией: `npx -y pkg@1.2.3`, `uvx pkg==1.2.3`, `docker run … image:tag`. Если его нет, берётся удалённый `streamable-http` на https. Плавающие версии и идентификаторы с посторонними символами отклоняются, описание проходит сканер. Эффекты `exec + network + write`, поэтому всегда нужен апрув, и в запросе видны команда и нужные секреты. План, показанный при апруве, кэшируется и исполняется именно он. После установки сервер пишется в конфиг и сразу запускается (или ждёт `august secret set`), новые тулы доступны уже в этой задаче.
- `install_skill`: навык из папки GitHub. Скачивается только `SKILL.md` (скрипты не ставятся: это был бы код от вашего имени), текст проходит сканер.

Навыки лежат в `~/.august/skills/<имя>/SKILL.md` и становятся тулами `skill.<имя>` с эффектом `read`: вызов возвращает инструкции. Навык может направлять агента, но каждое действие по-прежнему проходит политику.

## Каналы и апрувы

Все каналы идут через одну функцию `App.handle(session, text, approver)`; у каждой сессии свой апрувер. Сессии обрабатываются по одной задаче за раз (Lane Queue), поэтому ответ на запрос апрува нельзя ставить в ту же очередь: задача ждёт апрув, апрув ждал бы задачу. `PendingApprovals` принимает ответ в обход очереди. Молчание 5 минут означает «нет».

- **Терминал**: вопрос `Allow once? [y/N]`.
- **Веб-чат** (`august serve`): страница на `/` без внешних ресурсов, строгий CSP, текст выводится только через `textContent`. Токен приходит во фрагменте URL (`#token=…`), который браузер не отправляет на сервер, и сразу убирается из адресной строки. Пока ответ не пришёл, страница опрашивает `/v1/pending` и показывает кнопки, ответ уходит в `/v1/approve`.
- **Telegram**: long polling, без публичного вебхука. Отвечает только пользователям из `allowedUsers` в личных чатах, остальным не отвечает вовсе. Апрув даётся кнопками или ответом «да / yes»; любой другой ответ означает «нет». Токен бота берётся из хранилища секретов, в сообщения об ошибках URL с токеном не попадает.

## Секреты

`openSecretStore` выбирает лучшее, что есть: macOS Keychain (`security`), Secret Service на Linux-десктопе (`secret-tool`, значение идёт через stdin), иначе `~/.august/secrets.json` с правами 0600 (не зашифрован, как `.env`). Поиск значения идёт сначала в хранилище, потом в окружении, так что CI и контейнеры работают с обычными переменными. В конфиге хранятся только имена.

## Безопасность

- Каждый тул объявляет **эффекты**: `read`, `write`, `network`, `send`, `pay`, `delete`, `exec`.
- Данные из недоверенных источников получают метку **taint** и не могут управлять действиями с внешним эффектом без явного апрува.
- **Мандаты** дают агенту ограниченные по срокам, эффектам и лимитам полномочия.
- Новая версия навыка не может иметь эффектов шире предыдущей без апрува.
- Безопасность не полагается на модель: red-team набор (`packages/app/test/redteam.test.ts`) гоняет «послушную» модель, которая выполняет любую инъекцию, и проверяет, что наружу ничего не уходит без апрува, а логи не содержат ни секретов, ни заражённых примеров.
- Подробнее: [THREAT_MODEL.md](THREAT_MODEL.md).
