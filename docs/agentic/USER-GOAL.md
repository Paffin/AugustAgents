# Агент-платформа на Laya: архитектура и подводные камни

Sep 29, 2026 · @Max

## Резюме

Строим локальный always-on агент класса OpenClaw / Hermes Agent: шлюз к мессенджерам, память, самообучение и самостоятельное подключение скилов, плагинов и MCP-серверов. Установка — три действия: запустить установщик, выбрать «мозг», подключить канал.

**Позиционирование: агент следующего поколения, спроектированный под модели 2028 года.** Главная ставка — лестница дистилляции: каждая повторяющаяся задача проходит путь от LLM к «рефлексу» на Laya и коде, поэтому агент с использованием дешевеет и ускоряется, а не дорожает, как OpenClaw. Обучение проверяется исходом, а не самооценкой, как у Hermes, и рост виден пользователю. Безопасность строится на системе эффектов и мандатах, а не на бесконечных подтверждениях.

**Главный архитектурный вывод: Laya Multilingual не может быть единственной моделью агента.** Это негенеративная decision-модель на 322M параметров: она отвечает на типизированные вопросы (выбор из вариантов, да/нет) за один проход, но не пишет текст и не заполняет аргументы тулов. Поэтому схема двухслойная:

- **System 1 — Laya Multilingual (по умолчанию).** Выбирает, какой тул или скил вызвать, нужна ли новая способность, насколько рисковано действие, действовать самому или эскалировать. Десятки миллисекунд, локально, бесплатно.
- **System 2 — генеративная LLM на выбор пользователя** (локальная или по API). Заполняет аргументы по JSON-схеме, планирует многошаговые задачи, пишет ответы и новые скилы.

Второй ключевой факт: базовая Laya в zero-shot почти на уровне случайного угадывания на typed-decision задачах (0,342 против 0,318 у случайного). Значит, стартуем в теневом режиме: решения принимает LLM, Laya учится на её траекториях и забирает решения по мере того, как проходит eval. Это и есть наш «цикл обучения», только измеримый и дешёвый.

## Горизонт: проектируем под модели 2028 года

Архитектура должна выигрывать от выхода GPT-8 или Qwen 7, а не устаревать из-за него. Правило: **тонко там, где модели растут сами** (рассуждение, планирование, код), **толсто там, где рост моделей не помогает** — безопасность, состояние, идентичность, проверка результата, деньги.

| Что изменится к 2028 (наше допущение) | Что это значит для архитектуры |
| --- | --- |
| Токен дешевеет, но число шагов агента растёт быстрее | Оптимизируем не цену токена, а число вызовов LLM: дистилляция задач в код и решения Laya |
| Модели ведут задачи часами и днями | «Миссии» с вехами, бюджетом и чекпоинтами вместо разовых запросов |
| Контекст огромный, но внимание в нём неидеально и дорого | Память — проверяемый индекс с источниками, а не свалка в контекст |
| Нативный computer use становится нормой | Единый слой действий над API, MCP, браузером и экраном — с одной политикой безопасности |
| Вокруг тысячи агентов людей и компаний | Наш агент — участник сети: [A2A v1.0 с подписанными Agent Cards](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year) уже в продакшене у облаков |
| Агенты начинают платить | Кошелёк с мандатами и лимитами в духе [AP2](https://www.mintmcp.com/blog/ap2-agent-payments-protocol), а не карта в конфиге |
| Новые модели выходят каждые несколько недель | Автоматический экзамен каждой новой модели на личном eval-наборе и переключение без участия человека |
| Атаки автоматизируются и умнеют | Безопасность проверяется формально — по эффектам и потокам данных, — а не только эвристиками |
| Ужесточается регулирование ИИ и персональных данных | Локальность данных, неизменяемый журнал и объяснимость решений встроены с первого дня |

Три принципа, которые из этого следуют: не ставить против моделей (всё, что они скоро будут делать сами, держим заменяемым); каждое решение агента измеримо; доверие к навыку или модели зарабатывается проверенным исходом, а не объявляется.

## Изобретения следующего поколения

Главное отличие от OpenClaw и Hermes: наш агент **с каждым повтором задачи становится дешевле, быстрее и надёжнее — и это видно и проверяемо**. У OpenClaw главная жалоба пользователей — стоимость токенов и сломанные обновления ([дайджест экосистемы](https://github.com/kouweizhu/agents-radar/issues/219)); у Hermes — обучение, которого пользователь не видит ([обратная связь в трекере](https://github.com/NousResearch/hermes-agent/issues/125825)), и склонность хвалить самого себя ([разбор](https://blog.dailydoseofds.com/p/hermes-agent-masterclass)).

| Изобретение | Как работает | Что закрывает у конкурентов |
| --- | --- | --- |
| **Лестница дистилляции** | Повторяющаяся задача спускается по ступеням: LLM с нуля → навык → детерминированный workflow с развилками Laya → «рефлекс» без LLM. Сбой поднимает её обратно (схема ниже) | Стоимость токенов у OpenClaw; у Hermes навыки есть, но каждый запуск по-прежнему идёт через LLM |
| **Проверяемое обучение** | Навык повышается в ступени только по независимо подтверждённому исходу: тест, реакция пользователя, внешний сигнал (письмо дошло, задача закрыта). Самооценка агента не считается | Самопохвала и «misevolution» навыков в Hermes ([исследование](https://arxiv.org/pdf/2608.12851)) |
| **Видимый рост** | В чате — пометка «сделал по навыку X v3, 0 вызовов LLM»; раз в неделю — отчёт: что автоматизировано, сколько сэкономлено, что понизилось и почему | Невидимое обучение Hermes |
| **Система эффектов** | Каждый тул объявляет эффекты (читает / пишет / отправляет / платит / удаляет) и куда уходят данные. Политика проверяется до вызова, как типы в компиляторе; данные из недоверенных источников помечены и не могут управлять действиями с внешним эффектом | Prompt-инъекции и «заимствованные полномочия» навыков ([исследование](https://arxiv.org/pdf/2608.25091)) |
| **Мандаты вместо апрувов** | Пользователь один раз утверждает намерение с рамками: «оплачивать счета до 5 000 ₽ известным получателям в октябре». Агент получает токен-полномочие с лимитом и сроком; всё за рамками — спросить | Выбор между спамом подтверждений и вседозволенностью |
| **Спекулятивное исполнение** | Перед необратимым действием — прогон в форке: снимок файлов, черновик письма, мок API. Пользователь видит дифф «что изменится». Все действия пишутся в журнал событий, отменяемые — отменяются одной кнопкой | Необратимые ошибки агентов |
| **Экзамен моделей** | При выходе новой модели она автоматически проходит личный eval-набор пользователя; маршрутизация по типам задач переключается, если модель лучше или дешевле | Ручной выбор модели и дорогие дефолты |
| **Сам пишет недостающий MCP** | Если в реестрах ничего нет — агент пишет MCP-сервер, тестирует в песочнице, проверяет вторым независимым проходом на опасные эффекты и предлагает к установке | Тупик «навыка не существует» |
| **Коллективный иммунитет** | Добровольная федеративная сеть: хеши вредных пакетов, репутация издателей, федеративное дообучение Laya с дифференциальной приватностью — каждый пользователь улучшает решения для всех, не отдавая свои данные | Реестры без проверки, как ClawHub; сетевой эффект, которого нет ни у кого |
| **Гражданин сети агентов** | Своя идентичность и подписанная Agent Card (A2A): агент договаривается с агентами магазинов и сервисов, платит по мандату. Входящие агенты — всегда недоверенный ввод | Агенты-одиночки |
| **Миссии** | Долгие цели на недели: план, вехи, бюджет, регулярные отчёты, возобновление после сбоев; панель «центр управления» | Разовые сессии, которые теряются при рестарте |
| **Бюджет внимания** | Laya оценивает срочность и важность; у каждого прерывания есть «цена», мелочи уходят в дайджест, тихие часы соблюдаются | Спам проактивных сообщений |
| **Сетка устройств** | Одно состояние (CRDT) на ноутбуке, телефоне и VPS; вычисление идёт туда, где данные и нужное железо; работает офлайн | Жёсткая привязка к одному хосту |
| **Обновления без боли** | Два слота (A/B), репетиция миграции на копии данных, автооткат по health-check | Сломанные апдейты OpenClaw 2026.9.x |

## Слабые места первой версии и как закрыты

Первая версия схемы была хорошей копией OpenClaw + Hermes с Laya сверху. Ниже — где она ломалась бы и что меняем.

| Слабое место | Почему проблема | Решение |
| --- | --- | --- |
| Laya в теневом режиме в первый день бесполезна | Пользователь платит за LLM на каждый шаг, выгоды нет неделями | Поставляем свой предобученный чекпоинт «agent-decisions»: Laya, дообученная нами на синтетических и открытых траекториях вызова тулов, включая русский. Теневой режим остаётся только для персонализации |
| Шорт-лист ≤ 16 при тысячах тулов | Поиск может не поднять нужный тул, и Laya выберет лучший из неправильных | Иерархия домен → сервер → тул; ответ «ни один не подходит» запускает расширенный поиск; recall@16 — метрика в eval |
| Один процесс-шлюз | Одна ошибка роняет всё, как у OpenClaw с model-catalog worker | Акторная модель: каждый канал и MCP-сервер — изолированный процесс под супервизором с перезапуском и лимитами памяти/CPU |
| Качество зависит от выбранной LLM | Слабая локальная модель плохо заполняет аргументы | Ограниченное декодирование + валидаторы; дистилляция уводит частые задачи со ступени LLM; экзамен предупреждает, если модель не тянет |
| Апрувы утомляют | Люди начинают жать «да» не читая — защита превращается в ритуал | Мандаты, группировка похожих апрувов, риск от Laya; «апрувов в день» — метрика, которую снижаем |
| Отравление данных для дообучения Laya | Инъекция может научить Laya опасному выбору | В датасет попадают только примеры с подтверждённым исходом и без недоверенного контекста; red-team кейсы в eval-гейте |
| Самописные навыки расширяют себе права | Навык «улучшается» и начинает отправлять данные наружу | Новая версия навыка не может иметь эффектов шире предыдущей без апрува; сканер включён по умолчанию (у Hermes guard выключен по умолчанию) |
| Дубли навыков | Десять похожих навыков путают выбор | Дедупликация по эмбеддингам и по эффектам при создании; слияние с сохранением истории версий |
| Зависимость от внешних реестров | Реестр лёг или удалил пакет — навык не переустановить | Локальное зеркало всех установленных пакетов, работа офлайн |
| Не продумана проактивность | Heartbeat превращается в спам | Бюджет внимания и дайджесты |
| Правовые риски | Нарушение правил мессенджеров, обработка персональных данных, спор «кто разрешил» | Официальные API по умолчанию, данные локально, мандаты и неизменяемый журнал фиксируют, что именно было разрешено |
| Низкоресурсные языки | У Laya Multilingual заметно слабее качество на части языков | В первый день замеряем качество на языках пользователя; при низком — больше решений отдаём LLM, пока Laya не дообучится |

## Что берём у OpenClaw и Hermes и чем отличаемся

Берём лучшие паттерны обоих, но закрываем их известные провалы — прежде всего безопасность экосистемы скилов.

| Паттерн | Откуда | Берём? | Что меняем |
| --- | --- | --- | --- |
| Один процесс-шлюз + адаптеры каналов | OpenClaw | Да | Только loopback по умолчанию, проверка Origin, парный токен |
| Lane Queue: серийная очередь на сессию, отдельные лейны cron/subagent | OpenClaw | Да | + долговечные чекпоинты, чтобы задача переживала рестарт |
| Скилы как SKILL.md, прогрессивное раскрытие | Оба | Да | Совместимость с форматами обоих + подпись и сканирование |
| Память в файлах (md/yaml/jsonl) + SQLite FTS5 + векторы | Оба | Да | Провенанс каждой записи, защита от отравления памяти |
| Heartbeat (HEARTBEAT.md раз в N минут) и cron | Оба | Да | Laya решает «есть ли что сказать» — LLM не будится зря |
| Самосоздание и улучшение скилов, модель пользователя | Hermes | Да | Новая версия скила принимается только после eval, с откатом |
| Экспорт траекторий для дообучения | Hermes | Да | Траектории кормят дообучение самой Laya локально |
| Подключение любых MCP-серверов | Оба | Да | MCP — встроенный первоклассный гражданин, не скил-обёртка |
| Импорт настроек из конкурента | Hermes (из \~/.openclaw) | Да | Импорт из OpenClaw **и** Hermes на шаге установки |
| Доверие к публичному маркетплейсу без ревью | OpenClaw (ClawHub) | **Нет** | Проверки — в разделе про безопасность |
| Секреты открытым текстом в домашней папке | OpenClaw | **Нет** | Системное хранилище ключей (Keychain / Credential Manager / Secret Service) |

Почему это важно: у OpenClaw была RCE в один клик (CVE-2026-25253) из-за WebSocket без проверки Origin, а аудиты находили вредоносные инструкции в 12–20% скилов ClawHub ([разбор](https://blog.agentailor.com/posts/openclaw-architecture-lessons-for-agent-builders)). Агент, который **сам** ставит скилы из интернета, без встроенной проверки станет бэкдором. Это главное отличие, которое мы строим с первого дня.

## Laya Multilingual: что решает и как её не сломать

Laya принимает все «вилочные» решения агента; генеративная LLM вызывается только там, где нужен текст или аргументы. Факты о модели — из [карточки модели](https://huggingface.co/convaiinnovations/laya-multilingual): mmBERT-base, 322M, Apache 2.0, 100+ языков, \~33 мс на вопрос на T4, 103–332 вопроса/с батчем.

### Какие решения отдаём Laya

| Решение | Тип вопроса | Варианты |
| --- | --- | --- |
| Нужен ли тул вообще | choice | ответить сразу / вызвать тул / уточнить / нужна новая способность |
| Какой тул / скил вызвать | choice | до 16 кандидатов из шортлиста + «ни один не подходит» |
| Какой пакет из реестра ставить | choice | до 16 кандидатов из поиска по каталогу |
| Уровень риска действия | choice | чтение / запись локально / внешняя отправка / деньги или необратимое |
| Действовать или эскалировать | act/escalate-голова | сам / LLM / человек |
| Есть ли в выводе тула инструкции для агента | choice A/B | данные / попытка инъекции |
| Стоит ли записывать факт в память | choice A/B | долговременное / разовое |
| Heartbeat: есть ли что сообщить | choice A/B | молчать / разбудить LLM |
| Задача выполнена ли успешно (верификатор) | choice | готово / повторить / спросить пользователя |

### Схема вызова тула

1. Гибридный поиск (BM25 + эмбеддинги) по индексу всех тулов сужает сотни вариантов до ≤ 16.
2. Laya выбирает один из них или «ни один».
3. Если калиброванная уверенность ниже порога — тот же выбор делает LLM, а пара «вход → решение LLM» уходит в датасет дообучения.
4. LLM заполняет аргументы с ограниченным декодированием по JSON-схеме тула; валидатор проверяет схему.
5. Laya оценивает риск → политика решает, нужен ли аппрув → вызов в песочнице.

### Ограничения модели и наши обходы

| Ограничение (по карточке) | Решение |
| --- | --- |
| Zero-shot на typed decisions почти случайный (0,342 vs 0,318) | Теневой режим → дообучение (RLCD) на логах → включение по типу решения, когда совпадение с LLM на отложенной выборке выше порога |
| Поставляется некалиброванной, системно самоуверена | Температура на каждую пару (тип вопроса, число вариантов); перекалибровка после каждого дообучения |
| choice проседает после \~20 вариантов (256 токенов на вопрос и опции) | Шортлист ≤ 16, короткие описания тулов (≤ 12 токенов), иерархический выбор: сначала семейство, потом тул |
| Контекст 1024 токена по умолчанию (до 8192 явно, точность падает после \~4000) | В state — сжатый контекст: последнее сообщение, цель, резюме шага, а не вся история |
| `score` — самый слабый тип, позиционный сдвиг | Не используем `score`, только `choice` |
| `noul` занижает P(true) | Да/нет — как `choice` с нейтральными ключами A/B |
| Слабее английского чекпоинта на English | Multilingual — дефолт (как вы хотите), английский — опция в настройках через `Router(default="multilingual")` |
| `laya.load()` может зависнуть при установленном TensorFlow | В рантайме используем ONNX, Python — только для дообучения, с `USE_TF=0` |

**Инференс:** CPU — [ONNX INT8, 325 МБ, \~250–300 мс](https://huggingface.co/soyelmismo/laya-multilingual-onnx); Apple Silicon — [MLX-порт, \~7 мс](https://github.com/mizorewww/laya-mlx/wiki); NVIDIA — PyTorch/ONNX CUDA. Установщик выбирает вариант по железу сам. На слабом CPU батчим несколько вопросов в один проход.

## Архитектура

Один процесс-шлюз принимает сообщения, Laya решает за десятки миллисекунд, LLM вызывается только для генерации, а всё внешнее исполняется в песочнице после проверки политик.

## Установка и настройка в 3 касания

Всё, что можно определить самому (ОС, железо, язык, часовой пояс, установленные OpenClaw/Hermes), определяем сами — пользователь принимает только три решения.

1. **Запустить установщик.** Одна команда (`curl … | sh`, `irm … | iex` на Windows), десктопный инсталлятор или `docker run`. Ставит один подписанный бинарник, регистрирует службу (systemd / launchd / Windows Service), в фоне качает Laya в формате под железо и открывает веб-мастер на localhost. Если найден \~/.openclaw или \~/.hermes — предлагает импорт одной галочкой.
2. **Выбрать «мозг» (System 2).** Три кнопки: «Локально» (подбираем модель под VRAM/RAM и ставим рантайм), «Войти через провайдера» (OAuth), «Вставить API-ключ» (любой OpenAI-совместимый endpoint). Ключ сразу проверяем тестовым вызовом и кладём в системное хранилище секретов.
3. **Подключить канал.** QR-код или deep-link: Telegram-бот создаётся и привязывается сам, остальные каналы — позже. Можно пропустить — тогда работаем в веб-чате и CLI. После привязки агент пишет первое сообщение сам.

Всё остальное — безопасные дефолты и настройка разговором: «подключи мою почту» → агент сам находит MCP, запускает OAuth и присылает ссылку.

**Подводные камни установки и что делаем:**

- **Заблокированные или медленные Hugging Face / GitHub / npm.** Зеркала с проверкой sha256, поддержка HTTP(S)\_PROXY, офлайн-бандл «всё в одном архиве», докачка с места обрыва.
- **Зависимости MCP-серверов (Node, Python, Docker).** Не требуем их заранее: свой менеджер рантаймов (встроенный uv + Node) ставит нужную версию в свою папку по требованию.
- **Windows без WSL.** Нативная сборка с первого релиза; песочница — AppContainer/Job Objects, Docker — опция.
- **Слабое железо и VPS без GPU.** Laya INT8 на CPU + удалённая LLM; локальную LLM предлагаем, только если она реально потянет.
- **Повторная установка и поломки.** Идемпотентный установщик, команда `doctor` (диагностика и автопочинка), чистый `uninstall` с выбором «оставить данные».
- **Обновления.** Подписанные релизы, каналы stable/beta, автооткат при упавшем health-check, миграции схемы данных с бэкапом до них.

## Автоподключение скилов, плагинов и MCP

Агент сам находит, ставит, настраивает и удаляет способности — но через единый конвейер с проверкой доверия, песочницей и откатом. Единица учёта — **Capability**: общая обёртка над SKILL.md, MCP-сервером (stdio / Streamable HTTP), плагином OpenClaw или Hermes и встроенным тулом. У каждой — манифест: источник, версия + хеш, права (сеть, файлы, секреты), уровень доверия, статистика использования.

### Конвейер

1. **Обнаружить потребность.** Laya отвечает «нужна новая способность», либо тул упал, либо пользователь просит прямо. LLM формулирует запрос в терминах задачи («читать и создавать задачи в Jira»).
2. **Найти кандидатов.** Поиск по локальному каталогу, который раз в сутки синхронизируется с реестрами: официальный MCP Registry, ClawHub, каталог плагинов Hermes, agentskills.io, GitHub, npm/PyPI. Поиск локальный — быстрый и не сливает запросы пользователя наружу.
3. **Выбрать.** Laya ранжирует ≤ 16 кандидатов; финальный скор учитывает доверие источника. При прочих равных: официальный сервер вендора > проверенный из реестра > сообщество.
4. **Проверить.** Подпись и происхождение (sigstore/аттестации), возраст и репутация издателя, статический скан кода и зависимостей, скан текста SKILL.md и описаний тулов на скрытые инструкции (Laya-классификатор + LLM-ревью), сравнение заявленных прав с реальным кодом.
5. **Показать план и спросить.** Одна карточка: что ставим, откуда, какие права и секреты нужны. Уровень аппрува — по таблице ниже.
6. **Установить в песочницу.** Каждый MCP-сервер — отдельный процесс в контейнере / gVisor / bubblewrap / AppContainer, сеть по allowlist доменов из манифеста, файлы — только своя папка. Версия закрепляется хешем.
7. **Настроить.** OAuth — ссылка в чат (device flow или redirect на localhost), API-ключ — защищённая форма в веб-UI, **не в чат мессенджера**. Секрет попадает только в окружение этого сервера и никогда — в контекст LLM.
8. **Smoke-тест.** `list_tools`, один безопасный read-вызов. Не прошёл — откат и следующий кандидат (максимум 3 попытки, потом спрашиваем человека).
9. **Зарегистрировать.** Тулы — в индекс с неймспейсом `сервер.тул` и коротким описанием для Laya. В контекст LLM схемы попадают только когда тул выбран.
10. **Сопровождать.** Метрики ошибок и латентности; автоотключение при серии сбоев; обновление — только с диффом описаний тулов и прав (изменились → повторный аппрув); неиспользуемые 30 дней — предложить удалить.

### Уровни доверия и аппрува

| Уровень | Что сюда попадает | Установка | Вызов |
| --- | --- | --- | --- |
| Verified | Подписано вендором или нашим ревью, только чтение | Авто, с уведомлением | Авто |
| Known | Популярное, без находок сканера | Один аппрув | Чтение — авто, запись — спросить один раз |
| Community | Новое, мало установок, неподписанное | Аппрув + показ прав | Каждое действие с записью — спросить |
| Self-made | Скилы, написанные самим агентом | Авто, если только текст и прошёл eval; с кодом — аппрув | Как у тулов, которые скил вызывает |
| Blocked | Находки сканера, денылист сообщества | Никогда | — |

Независимо от уровня: отправка сообщений от имени пользователя новым адресатам, деньги, удаление и другие необратимые действия — всегда с подтверждением, если пользователь явно не создал правило-исключение.

## Подводные камни и решения

Самый опасный класс проблем — инъекции через сторонние скилы и вывод тулов: агент с доступом к почте и правом ставить код из интернета — идеальная цель. Остальные строки сортированы по убыванию ущерба.

### Безопасность

| Камень | Что может случиться | Решение |
| --- | --- | --- |
| Непрямая prompt-инъекция (письмо, сайт, файл) | Агент выполняет команду из чужого текста, сливает данные | Метки происхождения (taint) на всём внешнем; если в контексте есть недоверенные данные, действия с внешним эффектом — только через аппрув; Laya-детектор инструкций в выводе тулов |
| Вредоносные скилы и MCP в реестрах | Как ClawHub: эксфильтрация, вредоносное ПО | Конвейер доверия + песочница + общий денылист с телеметрией по желанию |
| Rug pull: MCP-сервер меняет описания тулов после установки | Вчерашний безопасный сервер сегодня даёт инъекцию | Пин хеша и снимка описаний; любое изменение → стоп и повторный аппрув |
| Подмена тулов (одинаковые имена) | Злой сервер перехватывает вызов `send_email` | Обязательные неймспейсы `сервер.тул`, описание одного сервера не может ссылаться на другой |
| Открытый шлюз / отсутствие проверки Origin | RCE в один клик, как CVE-2026-25253 | Bind только на 127.0.0.1; удалённый доступ — через Tailscale/WireGuard или парный токен; строгая проверка Origin и CSRF; токен никогда в URL |
| Секреты открытым текстом | Инфостилер забирает все токены | Системный keychain; на сервере — шифрование с ключом вне папки данных; редакция секретов в логах |
| Секрет попал в контекст LLM | Ключ уходит облачному провайдеру или в ответ | Секреты — только по ссылке (`secret://jira`), подстановка в рантайме; фильтр исходящих сообщений |
| Отравление памяти | Инъекция сохраняется как «факт» и срабатывает через неделю | В память пишем только из слов пользователя; записи из внешних источников помечены и не исполняются как инструкции |
| Самописные скилы деградируют | «Улучшение» ломает рабочий процесс | Версии в git, eval-набор на скил, включение только при не худшем результате, автооткат |
| Необратимое действие по ошибке | Удалённые файлы, отправленное письмо, платёж | Dry-run для записи, снапшоты, корзина вместо удаления, задержка отправки 30 с с кнопкой «отменить» |
| Чужой человек пишет боту | Посторонний управляет агентом | Allowlist владельцев на каждый канал; в групповых чатах — только чтение и ответ без тулов |

### Надёжность и эксплуатация

| Камень | Решение |
| --- | --- |
| Раздувание контекста при сотнях тулов | Схемы тулов не лежат в промпте: поиск → Laya → схема только выбранного; обрезка больших ответов тулов с полным текстом в файле |
| Зацикливание и сжигание бюджета | Лимит шагов и денег на задачу, детектор повторяющихся вызовов, эскалация человеку |
| Гонки при нескольких сообщениях подряд | Lane Queue; новое сообщение во время задачи — вливается как уточнение или «стоп» |
| Рестарт посреди длинной задачи | Долговечные чекпоинты в SQLite, идемпотентные ключи вызовов, продолжение с места остановки |
| Протухшие OAuth-токены | Авто-refresh; если не удалось — сообщение со ссылкой на перелогин, а не тихие ошибки |
| Бан аккаунта за неофициальный клиент мессенджера | По умолчанию — только официальные Bot/Business API; неофициальные мосты — опция с явным предупреждением и rate-limit |
| Лимиты и сбои LLM-провайдера | Цепочка фолбэков, экспоненциальный backoff, при полном отказе — Laya отвечает шаблоном «сделаю позже» и ставит в очередь |
| Дрейф Laya после дообучения | Замороженный eval-набор; новая версия весов включается, только если не хуже старой; храним 3 последние |
| Часовые пояса и тихие часы | Все расписания — в IANA-зоне пользователя; проактивные сообщения ночью копятся в утренний дайджест |
| Приватность | Никакой телеметрии по умолчанию; пометка каждого запроса, уходящего в облако; режим «только локально» |
| Лицензии сторонних скилов | Лицензия — поле манифеста; коммерчески несовместимые помечаются для командного режима |

## Стек, репозиторий и дорожная карта

Предлагаю TypeScript на Bun: один бинарник через `bun build --compile`, зрелый MCP SDK, совместимость с экосистемой OpenClaw. Python не нужен в рантайме — только для дообучения Laya, и ставится лениво через uv.

| Слой | Выбор | Почему |
| --- | --- | --- |
| Ядро, шлюз, очереди | TypeScript + Bun | Один бинарник, быстрый старт, MCP SDK |
| Laya-инференс | ONNX Runtime (CPU/CUDA/CoreML), MLX на Mac | Без Python, INT8 325 МБ |
| Дообучение Laya | Python-сайдкар `pip install laya` через uv, экспорт в ONNX | Официальный путь RLCD |
| Хранение | Файлы + SQLite (FTS5, sqlite-vec) | Локально, читаемо, бэкап копированием |
| Песочница | bubblewrap / gVisor (Linux), sandbox-exec (macOS), AppContainer (Windows), Docker — опция | Изоляция без обязательного Docker |
| Секреты | OS keychain через keytar-аналог; age-шифрование на серверах | Нет plaintext |
| Веб-UI | SvelteKit, вшит в бинарник | Мастер установки, аппрувы, журнал, память |
| Наблюдаемость | OpenTelemetry → локальный файл / любой OTLP | Дебаг решений |

```
agent/
  core/          шлюз, lane queue, чекпоинты, политики
  brain/
    laya/        ONNX-рантайм, шаблоны вопросов, калибровка
    llm/         провайдеры, фолбэки, ограниченное декодирование
  capabilities/
    registry/    синхронизация каталогов, поиск
    trust/       подписи, сканеры, денылист
    adapters/    mcp, skill-md, openclaw, hermes
    sandbox/     изоляция по ОС
  memory/        файлы, индексы, модель пользователя
  channels/      telegram, web, cli, slack, discord, email, ...
  learning/      траектории, eval, дообучение laya (python)
  ui/            SvelteKit
  installer/     install.sh, install.ps1, детект железа, импорт
  evals/         замороженные наборы решений и red-team кейсы
```

**Как измеряем успех:** время от запуска установщика до первого ответа в Telegram; доля решений, принятых Laya без LLM; доля успешных автоустановок с первой попытки; процент red-team кейсов инъекций, заблокированных до действия; стоимость токенов на задачу в сравнении с «чистой LLM».
